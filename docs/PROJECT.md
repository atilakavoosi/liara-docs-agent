# لیارایار — دستیار هوشمند مستندات لیارا

## ۱. مشکل با کلمات خودم

لیارا سریع سرویس اضافه می‌کنه و مستنداتش هم‌پای اون رشد کرده — الان ۱۱۴۲ صفحه‌ی
مستندات داره. بار پشتیبانی‌شون عمدتاً باگ نیست؛ **شکست ناوبری و شکست فهم** ـه:
کاربر یا سند درست رو پیدا نمی‌کنه، یا پیدا می‌کنه و نمی‌تونه به موقعیت خودش ترجمه‌اش کنه.

**جایی که برداشتم با متن اسپانسر فرق داره:** لیارا صورت‌مسئله رو «جستجوی بهتر
در مستندات» گذاشته. ولی جستجو فقط نصف ماجراست. یک کاربر که تایپ می‌کنه
«دیپلویم ارور خورد» اصلاً یک کوئری جستجو نداره — یک *لاگ* داره و یک هدف.
پس محصول باید از «موتور جستجوی بهتر» فراتر بره و **کار عیب‌یابی رو انجام بده**،
نه اینکه لینک تحویل بده. این توضیح می‌ده چرا امتیاز agentic (۵۰) رو جدا گذاشتن.

## ۲. کاربر هدف

توسعه‌دهنده‌ای که همین الان وسط کار روی لیارا گیر کرده — معمولاً موقع اولین
دیپلوی یا موقع وصل کردن یک سرویس به سرویس دیگه. عجله داره، مستندات رو کامل
نمی‌خونه، و آستانه‌ی رفتنش سمت تیکت پایینه. کاربر ثانویه: تیم پشتیبانی لیارا
که سود می‌بره اگه تیکت‌های رسیده از قبل ساختاریافته باشن.

## ۳. MVP scope

### Must-have (بدون این‌ها دمو معنی نداره)
- بازیابی هیبرید روی هر ۱۱۴۲ سند، با نرمال‌سازی فارسی
- پاسخ استریم‌شده با **ارجاع درون‌متنی به URL واقعی docs.liara.ir**
- سؤال تکمیلی وقتی intent مبهمه
- حفظ context مکالمه بین تِرن‌ها
- دیپلوی زنده روی زیرساخت لیارا
- Rate limiting + مدیریت خطا + مخفی‌سازی کلید

### Should-have (اگه وقت موند)
- عیب‌یابی از روی لاگ خطای پیست‌شده
- تولید `liara.json` / Dockerfile متناسب با استک کاربر
- Runbook چندمرحله‌ای با حفظ progress
- پروفایل شخصی‌سازی (استک، پلن، سرویس‌های در حال استفاده)
- داشبورد `/admin` برای مصرف توکن و نرخ کش

### Explicitly Cut (وسوسه‌انگیز، ولی رسماً کنار گذاشته شد)
- **احراز هویت کاربر** — هیچ معیار داوری‌ای بهش امتیاز نمی‌ده. پروفایل رو
  بدون لاگین در session نگه می‌داریم.
- **دیتابیس و pgvector** — کورپوس ۵.۴ مگابایته. ایندکس استاتیک سریع‌تر،
  ارزون‌تر و برای دیپلوی ساده‌تره. (ADR-003)
- **پشتیبانی چندزبانه** — مستندات فارسیه، داورها فارسی‌زبان‌ن. فقط فارسی.
- **تاریخچه‌ی مکالمات ماندگار بین دستگاه‌ها** — نیاز به حساب کاربری داره.
- **صدا / آپلود تصویر** — به مشکل اصلی ربطی نداره.
- **fine-tune کردن مدل** — در بازه‌ی ۳۳ ساعته غیرممکن و بی‌فایده.

## ۴. Definition of Done برای دمو

روی صحنه، روی URL زنده‌ی لیارا، این پنج سناریو بدون دست‌کاری اجرا می‌شن:

1. **سؤال ساده:** «چطور یک برنامه Next.js رو روی لیارا دیپلوی کنم؟»
   → پاسخ درست و مرحله‌به‌مرحله با لینک به سند واقعی.
2. **سؤال مبهم:** «دیتابیسم وصل نمی‌شه»
   → به‌جای حدس زدن، **سؤال تکمیلی می‌پرسه** (کدوم دیتابیس؟ از کدوم پلتفرم؟).
3. **عیب‌یابی:** پیست کردن یک لاگ خطای واقعی
   → خطا رو تشخیص می‌ده، سند `fix-common-errors` منطبق رو پیدا می‌کنه، راه‌حل می‌ده.
4. **پیگیری context:** «حالا همین رو برای Laravel بگو»
   → می‌فهمه «همین» به چی برمی‌گرده، جواب رو برای استک جدید بازنویسی می‌کنه.
5. **صداقت:** سؤالی که مستندات جوابش رو نداره
   → توهم نمی‌زنه؛ محدودیت رو اعلام می‌کنه و **پیش‌نویس تیکت پشتیبانی** می‌سازه.

بعلاوه: `/admin` رو باز می‌کنیم و توکن مصرف‌شده و نرخ اصابت کش رو نشون می‌دیم.

|---|---|---|
| کیفیت و صحت پاسخ | ۸۰ | بازیابی هیبرید + rerank + eval عددی + citation اجباری + رفتار «نمی‌دونم» |
| UI و تجربه کاربری | ۵۵ | RTL فارسی، استریم، کارت منبع، کدبلاک کپی‌شو، پنل شفافیت، ریسپانسیو |
| Agentic و شخصی‌سازی | ۵۰ | intent router، سؤال تکمیلی، runbook، پروفایل، پیشنهاد قدم بعدی، تیکت‌ساز |
| امنیت، پایداری، مانیتورینگ | ۵۰ | rate limit، zod، کلید سمت سرور، error boundary، لاگ ساخت‌یافته، health |

## ۶. ریسک‌ها (به ترتیب اولویت اسپایک)

1. **مسیر دیپلوی لیارا** — قبل از هر کد دیگه‌ای تست شد. بلوک ۰.
2. **کیفیت بازیابی فارسی** — بزرگ‌ترین ریسک باقی‌مونده و مستقیماً روی ۸۰ امتیاز
   اثر داره. با eval عددی در ساعت ~۱۲ سنجیده می‌شه، نه شب آخر.
3. **پایداری/سرعت سرویس AI لیارا** — ناشناخته‌ی خارج از کنترل ما. timeout و
   retry و پیام افت تدریجی، بعلاوه ویدیوی دمو به‌عنوان بیمه.
4. **حجم ایندکس در حافظه‌ی کانتینر** — اندازه‌گیری بشه؛ در صورت نیاز int8.
